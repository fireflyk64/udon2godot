# Session notes, 2026-09-17: the sandbox rejects, the packages tell

Everything below is on `main` (`fireflyk64/udon2godot`), with the matching dependency forks:
`fireflyk64/godot-sandbox` branch `udon2godot` at `4d58be8` (compiler fixes, MAX_LEVEL 16) and
`fireflyk64/unidot_importer` branch `udon-integration` at `3458439`. `scripts/setup_deps.sh`
fetches both.

## What was done

**1. Every converted script now compiles in the sandbox (362 of 362, was 197).**
`udon2godot --check` reporting no errors said nothing about whether the sandbox's SafeGDScript
compiler accepts the output. The new `scripts/compile_check_refs.sh` converts every repository
under `refs/` and loads each script; its first run failed 165 scripts. All causes were fixed in
the converter (commit `f1e44a6`):

- `public new const int X` hiding a base constant (UdonUtils does it in every class) → the hiding
  member gets a class-qualified name (`ExecutionOrder_AudioEvent`), resolved per class chain.
- `string s = null`, `return null` from string methods, null for `System.Type` / `VRCUrl`
  → `""` stands for a null string everywhere; `== null` on those also tests `""`.
- Arrays / `DataList` / `DataDictionary` that the sources set to, compare with or return as null
  → SafeGDScript nullable types (`Array?`, `Dictionary?`), found by a syntactic scan
  (`src/nullflow.rs`). A non-serialized array field starts null, so the common
  `if (cache == null) cache = new T[n];` finally runs.
- `default` takes the type of its target; enum blocks are inherited from base scripts instead of
  redeclared; abstract / virtual / override properties go through `get_X()` / `set_X()`.
- Overloads along a class chain: `override Foo(int)` was emitted under the wrong base name and
  replaced the wrong method; overrides now carry the name of the base overload they match.
- `a ?? b` evaluated `a` up to three times.

**2. UdonUtils' own runtime test scene runs inside an imported world** (`scripts/test_world_community.sh`,
world `udonutils_tests`). The package's two TestControllers run 17 cases; the 7 single-player
ones pass, the 10 that need two players say so. What it exposed and what was fixed at the source:

- The default (single-player) provider never raised `OnPlayerRestored`, and local `PlayerData`
  writes never raised `OnPlayerDataUpdated`; both do now (one batched call per frame, with
  `PlayerData.Info` states). PlayerData can persist between sessions (`--player-data <file>`,
  `--play` uses `user://udon_player_data.dat`); the network provider's server store switched from
  JSON to typed variant storage (JSON turned Vector3 into text and ints into floats).
- Generic user methods: `GetComponent<T>()`, `typeof(T)`, `x is T`, `GetUdonTypeName<T>()` inside
  a generic method used the literal "T". Type arguments now travel in hidden leading
  `_T_<name>: String` parameters (inferred from `out` / `ref` arguments too).
- `base.OnPlayerRestored(p)` (or any `base.Event()`) with no converted base defining it became
  `super.X()`, which the sandbox dispatches back to the override → recursion to the VM depth
  limit. Such calls into UdonSharpBehaviour are now empty; `base.SendCustomEvent(...)` goes to the
  catalog.
- Catalog aliases for nested C# type names: `PlayerData.Info`, `PlayerData.State` (new enum),
  `Button.ButtonClickedEvent`, `Slider.SliderEvent`, `VRCPhysBoneBase.ImmobileType`, ...

**3. A SafeGDScript compiler bug in godot-sandbox** (fork `4d58be8`, regression test):
`var n: Node3D = null` followed by `n = items[0]` left the register typed NIL, so `n == self`
folded to **false at compile time** and `n = self` was rejected. Converted code uses this shape
constantly (`Node x = null; x = ...; if (x == other)`). Class-typed locals that start null are
untyped storage now, like `var n = null`.

**4. Test apparatus**: scenarios must return `true` (a run whose scenario died on a script error
used to print PASSED with one check); `SCRIPT ERROR` lines fail world suites; stale-import
detection compares a fresh manifest with the one the world was imported with; `verify.sh` fails
on compile-check failures; `ci.sh` runs the all-refs compile check.

**Results** (last runs): coverage 963 / 0 (18 fixtures; `TNulls.cs` is new with 32 checks),
verify e2e 0 failures + compile 108 / 0, net test 0 failures, all-refs compile 362 / 0; fixture
96 / 131 / 25 / 16, billiards 9 + 17, EmyChess 20 + 20, UdonEssentials 17 + 17 (those four ran on
commit `f1e44a6`, before the last batch; coverage / verify / net ran on the final tree).

**What went wrong**: to run the display pass of the 148-script UdonUtils world I raised
`GODOT_VMEM_MB` to 16384 for one run, which crashed the machine out of memory. The caps in
`scripts/godot.sh` are not tunables; that world is headless-only now (`test_world_community.sh`),
and the rule is in my memory notes.

## Trying it on your machine

Requirements: Linux x86_64, Rust (cargo), `curl`, `unzip`, `git`, `python3`; an X display for
anything interactive. Everything else is fetched.

```sh
git clone git@github.com:fireflyk64/udon2godot.git && cd udon2godot
scripts/setup_deps.sh                # Godot 4.7.2, sandbox binaries, refs/ (pool table, vrcbce, Sacc)
scripts/setup_deps.sh --community    # EmyChess, UdonEssentials, UdonUtils, ... (pinned commits)
cargo build --release
```

### Convert one script and look at the output

```sh
target/release/udon2godot -o /tmp/out tests/coverage/TNulls.cs     # two classes → two .sgd files
sed -n 1,80p /tmp/out/TNulls.sgd
target/release/udon2godot --check --report refs/EmyChess            # warnings / API usage, no output
```

### The quick suites (headless, a few minutes)

```sh
scripts/verify.sh                 # cargo tests, corpus conversion, e2e lifecycle, sandbox compile check
scripts/coverage_test.sh          # 18 C# fixtures executed in Godot: 963 checks
scripts/coverage_test.sh TNulls   # just one fixture
scripts/compile_check_refs.sh     # every repo under refs/ converts to scripts the sandbox compiles
```

### Play the pool table

```sh
scripts/import_world.sh refs/MS-VRCSA-Billiards /tmp/worlds/billiards   # ~10 min the first time
scripts/play_world.sh /tmp/worlds/billiards
```
WASD / arrows move, Shift runs, Space jumps, the mouse looks, click = use / grab, Esc or Tab frees
the mouse to click the canvases (lobby → join → 8-ball → break). The automated version of the same
game is `scripts/test_world_billiards.sh /tmp/worlds/billiards` (headless scenario, then a
window-input pass with screenshots in `/tmp/worlds/billiards/shots`).

### Play chess, or the UdonEssentials example

```sh
scripts/import_world.sh refs/EmyChess/Packages/com.emymin.emychess/Runtime /tmp/worlds/emychess
scripts/play_world.sh /tmp/worlds/emychess res://Runtime/ExampleScene.tscn

scripts/import_world.sh "refs/UdonEssentials/Assets/Varneon/Udon Prefabs" /tmp/worlds/essentials
scripts/play_world.sh /tmp/worlds/essentials "res://Assets/Varneon/Udon Prefabs/Essentials/Examples/UdonEssentials_ExampleScene.tscn"

scripts/test_world_community.sh /tmp/worlds        # the scripted versions: 20 + 17 + 6 checks
ONLY=emychess scripts/test_world_community.sh /tmp/worlds
```

### UdonUtils' own test cases (headless)

```sh
scripts/import_world.sh refs/UdonUtils/Packages/tlp.udonutils/Runtime /tmp/worlds/udonutils
scripts/godot.sh --headless --path /tmp/worlds/udonutils -s world_runner.gd -- \
    --scene res://Runtime/Scenes/Examples/RuntimeTesting/RuntimeTestingExample.tscn \
    --frames 5 --scenario res://scenarios/udonutils_tests.gd --player-data /tmp/worlds/udonutils/pd.dat
```
The scenario prints each of the package's 17 verdicts and its own 6 checks; run it twice to see the
persistence case pass on the revisit. Do not run this world on a display: 148 sandboxes plus the GL
driver exceed the address-space cap (see above).

### The hand-written Unity fixture, interactively

```sh
scripts/test_unity_fixture.sh /tmp/worlds/fixture       # imports tests/unity_fixture, 4 scenarios
scripts/play_world.sh /tmp/worlds/fixture               # walk around it; click the buttons
scripts/world_doctor.py /tmp/worlds/fixture             # what converted, what did not, why
```

Every Godot start goes through `scripts/godot.sh` (6 GB resident cap, 8 GB address-space cap,
lifetime cap except when playing). `GODOT_BIN=/path/to/godot` selects another engine binary.
